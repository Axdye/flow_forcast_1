# 工作故事线：结构化多候选能否被历史路由压缩为一次预测

## 1. 一句话故事

在一个已有交通流预测器上学习少量具有时序与图传播结构的残差候选，训练时用真实未来确定候选质量，再检验历史中是否存在足够信息，让一个预解码路由器选择有用的修正，以单候选解码成本改善预测。

暂定名称：**SBoN-Adapter（Structured Best-of-N Adapter）**。

暂定题目：**Structured Candidate Search and Pre-Decoding Routing for Traffic Flow Forecasting**。在结果证明实际保留搜索收益后，可使用 “From Many Futures to One” 副标题。名称不承担新颖性证明。

## 2. 从旧工作继承什么，改变什么

旧工作使用随机预测、组内比较与所谓 GRPO 更新。本项目延续交通流任务和多候选观察，但重新定义为监督多假设预测。真实未来提供监督成本，不需要环境交互、策略比率、PPO clipping 或 reference policy。旧结果不能平移成新方法结果。

复用的是已下载数据、可追溯的原始 backbone、数据格式知识和对照实现思路。训练器、oracle、router、连续一致性代价及评估协议重新实现。旧 GRPO reward 不参与新 loss。

## 3. 修正最重要的理论缺口

对于平方损失，理想的确定性预测是条件均值；绝对损失对应条件中位数。若候选之间的差别完全由历史不可观测的随机事件造成，任何只看历史的 Router 都不可能知道哪个未来会实现。

因此，不能用“未来多模态”直接推出“Top-1 路由一定更好”。更稳妥的假设是：**有限容量、有限数据下的现有 backbone 存在历史可辨识的系统性误差，结构化残差候选能够刻画这些误差模式，路由器能利用其中可预测的一部分。**

Oracle 衡量候选集合对已实现未来的覆盖能力；Router 衡量这种覆盖优势中可由历史预测的部分。两者必须分别检验。

流量升降不等于拥堵形成/消散。没有速度、密度或独立事件标注时，正文使用“流量上升/下降/高波动阶段”，不把模型参数称为真实拥堵因果变量。

## 4. 四个可证伪假设

| 编号 | 假设 | 支持证据 | 失败后的结论 |
|---|---|---|---|
| H1 | 结构化残差形成有效候选集 | 同预算下 MAE-oracle 优于单适配器及无结构候选 | 结构未提供增益，不能继续强调结构创新 |
| H2 | 候选优劣部分可由历史预测 | 时间留出 probe 的 regret 与预测 MAE 优于先验/固定分支 | 停止 Top-1 摊销主张 |
| H3 | 可部署 Router 的收益超过增加参数带来的收益 | Router@1 优于匹配参数单适配器、成本可接受 | 只是容量增加，贡献需收缩 |
| H4 | 插件接口与收益可迁移 | Frozen 模式跨至少三类 backbone、两个数据集验证 | 只能写特定 backbone 改进 |

H1 不蕴含 H2，H2 不蕴含 H3。Top-1 分类准确率也不直接蕴含预测收益，选错两个近似等价候选可能无害，选错一个高损失候选可能严重，因此 regret 和部署 MAE 比分类准确率更重要。

## 5. 方法因果链

### 5.1 从历史得到基础预测和表示

输入 X 为最近一小时 12 个五分钟 flow 观测，输出 Y 为未来一小时。backbone 产生基础预测和节点表示，projector 将不同架构的表示转换为统一维度。Frozen 主实验不修改基础模型参数或运行统计。

### 5.2 用共享低维动作提出多个修正

每个样本产生 K 个五维控制量：起始位置 o、hop 延迟 δ、正负幅度 m、持续跨度 d、衰减率 ρ。各候选共享解码器，只通过这些动作区别。它们是归纳偏置，不是已识别的物理参数。

v1 关闭自由局部分支、FiLM 平移和独立候选预测头，让模型不能绕开结构化路径。若必须增加自由旁路才能有效，需要作为不同方法版本重新评价结构主张。

### 5.3 监督未来提供候选成本

训练时计算每个完整候选的预测误差，以及非负、经验上包络、图变化等连续代价。使用停止梯度的软 oracle 权重分配非负候选损失，保留 loser floor，避免未被选中的分支完全失去监督。

经验上包络来自训练数据分位数，不是道路容量。图变化惩罚仅为平滑先验；真实流量可以有强空间差异，不能把低图变化直接称为“更符合物理”。

### 5.4 先冻结候选，再检验能否学习选择

冻结 backbone、projector、动作生成器和 decoder，使分支身份与训练标签稳定。先用线性/MLP probe 预测候选成本或分支，再训练正式 Router。

主方法 Router 仅接收历史表示。部署时先选动作，再仅解码该动作。训练中的 Y 不属于模型输入 API。未来日历也是可用性需要明确的协变量；v1 只使用历史日历，减少接口分歧。

### 5.5 归因与效率证据

K 个五维动作的生成仍随 K 增长，因此不宣称部署复杂度与 K 完全无关。可验证主张是：**高维候选轨迹只解码一条**。用 profiler、路径测试和延迟比较证明，不能只看函数调用计数。

## 6. 论文贡献的条件式表述

实验前可以写“我们设计/研究/检验”；不能写“显著提升”“解决了坍缩”“实现通用可插拔”。通过实验后，贡献可整理为：

1. 一个限制在图时空结构路径内的灰盒残差候选生成器。
2. 一个区分未来可见候选上界与历史可见部署选择的训练、诊断与压缩框架。
3. 一组跨骨干、同预算及失败案例证据，说明哪些候选收益可被一次路由保留。

soft-WTA、残差适配、蒸馏、混合专家和 Best-of-N 本身均不能被宣称为原创。候选语义与单解码的组合价值需要直接机制对照。TimeMCL/BOND/TimeKD 等来自旧稿的相关工作线索，当前不据此宣称已完成系统新颖性检索。

| 内容 | 论文图表 | 必须包含的反例/控制 |

## 9. 失败路线预先登记

- Oracle 无明显收益：检查实现和容量后停止扩展，优先产出可复现基线与负结果。
- Oracle 好而 Router 差：不能改用测试真值选分支；转为候选覆盖研究需要新研究设计，概率预测还需校准和 proper scoring rules。
- Router 只优于原 backbone、不优于同参数 single：不成立“搜索摊销优于容量增加”的贡献。
- Frozen 失败、Full 有效：定位为模型微调，不再强调参数高效插件。
- 结构控制干预失败：降级措辞为 structured latent controls；结构化机制是否仍有价值靠消融判断。
- 只改善经验约束：可以研究准确性—一致性权衡，但不能继续用准确率提升故事。

算力充足的意义是增加独立重复与公平对照，不是把科学失败用更多搜索掩盖。
